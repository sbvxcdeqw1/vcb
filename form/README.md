# Приём показаний ХВС/ГВС с сайта на Tilda

Форма на Tilda → Google Apps Script → Google Таблица → лист «Для 1С» в формате документа
«Ввод показаний индивидуальных приборов учета».

Файлы:

| Файл | Зачем |
|---|---|
| `tilda_block.html` | блок для Tilda (T123 «HTML») |
| `apps_script.gs` | код для Google Таблицы (Расширения → Apps Script) |
| `accounts.csv`, `meters.csv` | справочники лицевых счетов и приборов (в архиве; в репозиторий не кладутся) |
| `build_data.py` | собирает справочники из выгрузок 1С |
| `tests/` | тесты: `node form/tests/run.js`, `pytest form/tests` |

## Как работает форма

1. Жилец вводит **лицевой счёт** (12 цифр; в базе есть и 13-значный). При полном совпадении сразу видно «Квартира N»
   или «Помещение САС» (инициалы владельца, если номера квартиры нет). Список счетов на сайт не передаётся.
2. **Общая площадь из квитанции** — второй признак, чтобы чужие показания нельзя было подать, просто перебрав номера счетов.
   5 неверных попыток подряд — счёт блокируется на час. Отключается в «Настройках».
3. **Приборы квартиры берутся из базы 1С** (лист «Приборы»): жилец видит ровно свои приборы — «ХВС, ванная · №…5228»,
   «ГВС, кухня», «ХВС» и т.п. — и вводит показание для каждого. Если по счёту приборов в базе нет — ручной ввод
   (строки ХВС+ГВС, при двух строках обязательно «ванна/кухня»), в «Примечании» пометка «прибор не найден в базе 1С».
4. Значения приводятся к виду `27,124` (до 5 цифр, запятая, 3 знака); иначе — «Проверьте подлинность значения».
5. **Проверки по предыдущему показанию** (из 1С или принятому формой ранее — что свежее):
   меньше предыдущего — отправить нельзя («если прибор заменён — сообщите в УК»);
   расход больше порога (по умолчанию 15 м³ в месяц, с учётом числа месяцев) — форма просит подтвердить,
   в «Примечании» пометка. Сами предыдущие показания на сайте не показываются.
6. **Согласие на обработку персональных данных** — обязательная галочка со ссылками на согласие (`URL_CONSENT`) и политику
   (`URL_POLICY`). Тексты — `consent_block.html` и `policy_block.html` (блоки T123 для отдельных страниц Tilda; места `[[…]]` заполнить).
7. По желанию — **письмо-подтверждение** на e-mail жильца (настройка, по умолчанию выключено).

## Настройки (лист «Настройки», значение — в столбце B)

Настройки ищутся **по названию** в столбце A, порядок строк не важен; недостающие строки добавляются сами,
лишние (например, старое «Всего квартир») ни на что не влияют.

| Настройка | По умолчанию |
|---|---|
| День начала приёма / День окончания приёма | 20 / 25 (если окончание меньше начала — окно через границу месяцев, 28 → 3; показания 1–3 числа идут в прошлый период) |
| Приём включён | ДА |
| Текст при закрытом окне | «Показания принимаются с {start} по {end} число каждого месяца.» |
| Проверять площадь | ДА |
| Макс. расход в месяц, м³ | 15 |
| Подтверждение на почту | НЕТ (лимит Gmail ~100 писем в сутки) |

## Данные для 1С

В таблице появится меню **«Показания»** (после перезагрузки таблицы):

* **Сформировать лист «Для 1С»** — спрашивает период (по умолчанию текущий) и строит таблицу в столбцах и порядке
  документа 1С: N | Объект учета | Прибор учета | Заводской номер | Предыдущее показание | Текущее показание | Объем |
  Дата пред. показания | Дата показания | Комментарий.
* **Сформировать лист «Не подали»** — счета без показаний за период (для напоминаний и начисления по нормативу).

Лист «Показания» хранит всё принятое (повторная отправка за период заменяет строки счёта), «Журнал» — каждую отправку
с отметкой о согласии.

## Справочники: обновлять раз в месяц, после загрузки показаний в 1С

```bash
python3 build_data.py --accounts список_помещений.xlsx --meters ввод_показаний.xlsx -o папка
```

* `--accounts` — отчёт 1С «Список жилых помещений» (как вы присылали).
* `--meters` — один или несколько документов «Ввод показаний индивидуальных приборов учета»; для каждого прибора
  берётся самое свежее показание, оно станет «предыдущим». Лучше всего — полный список приборов дома, тогда ручной
  ввод почти не понадобится.
* Скрипт выводит, что пропустил: счета без приборов, приборы без лицевого счёта, нераспознанные названия.

Загрузка CSV в таблицу: лист → выделить всё → Delete → **Файл → Импорт → Загрузка** → «Заменить текущий лист»,
разделитель «Точка с запятой», **снять** «Преобразовать текст в числа, даты и формулы».

## Первая установка

1. Создайте Google Таблицу, **Файл → Настройки** — часовой пояс (Москва/Екатеринбург), регион «Россия».
2. **Расширения → Apps Script**, вставьте `apps_script.gs`, сохраните. Выберите функцию **`setup`** → «Выполнить» → разрешите доступ.
3. Загрузите `accounts.csv` в лист «Лицевые счета», `meters.csv` — в лист «Приборы».
4. **Начать развёртывание → Новое развёртывание → Веб-приложение**: от своего имени, доступ «Все». Скопируйте URL `/exec`.
5. В Tilda: блок **T123 «HTML»**, вставьте `tilda_block.html`, укажите `URL_API`, `URL_POLICY` и `URL_CONSENT`, опубликуйте страницу.

## Обновление с предыдущей версии

1. **Код:** Apps Script → удалить всё → вставить новый `apps_script.gs` → сохранить.
2. Выбрать функцию **`setup`** → «Выполнить» → разрешить доступ (появились новые разрешения: почта и кеш).
   Скрипт сам допишет недостающие настройки, а листы «Показания» и «Журнал» со старыми столбцами переименует
   в «… (старая версия …)» — данные не теряются.
3. **Справочники:** новый `accounts.csv` → лист «Лицевые счета» (теперь 4 столбца), `meters.csv` → **новый** лист
   «Приборы» (создан функцией `setup`).
4. **Развёртывание → Управление развёртываниями → карандаш → Версия: «Новая версия» → Развернуть.** Адрес не меняется.
5. **Tilda:** сохранить свой `URL_API` → заменить код блока новым `tilda_block.html` → вписать `URL_API`,
   `URL_POLICY` и `URL_CONSENT` (адреса страниц политики и согласия на вашем сайте) → «Опубликовать».
6. Проверка: Ctrl+F5 на сайте, введите любой счёт из листа «Лицевые счета» — должны появиться квартира и её приборы.

## Персональные данные

* Таблицу не открывайте посторонним: там лицевые счета, адреса и (если включено) e-mail.
* Google хранит данные за пределами РФ; по 152-ФЗ первичная запись ПДн граждан РФ должна вестись в базах на территории РФ.
  Оцените это с юристом; при необходимости серверную часть можно перенести (например, в Yandex Cloud Functions),
  блок на сайте останется прежним.
